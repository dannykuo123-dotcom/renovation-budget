# #1069 單層極簡帳本設計規格

## 目標

將工程帳本與新增帳務流程大幅減法，讓使用者不需閱讀說明文字或打開大量選單，就能完成篩選、查帳與新增收入／支出／轉移。

不修改後端 API、資料庫、資料模型、帳務計算方式與既有資料。

## 導覽

- 移除桌機左側欄，所有頁面改用頂部單層導覽。
- 導覽固定在視窗頂部，採半透明玻璃背景、柔和邊框與背景模糊。
- 左側顯示漸層動態 SVG 標誌、「彩虹室內設計」及英文點綴 `RAINBOW INTERIOR DESIGN`。
- 導覽項目依序為總覽、預算、帳本、設定。
- 目前頁面使用深色底與白字；未選項目維持透明底，hover 時顯示淡色背景。
- 右側保留重新整理與登出。
- 手機版維持同一列，可橫向滑動導覽項目，不改回側欄或底部導覽。

## 頁面標題

- 移除標題上方重複顯示的工程名稱。
- 頁面只保留單一主標題，例如「工程帳本」。
- 工程切換入口整合到品牌旁的精簡工程選擇按鈕，不另外占用一個資訊區塊。

## 帳本篩選

- 第一列為人員，直接顯示「全部」與人員首字頭像。
- 第二列合併類型與分類：
  - 類型固定顯示全部、收入、支出、轉移。
  - 分類緊接在類型右側；沒有分類時不顯示多餘空白區。
- 篩選容器取消三段直向排列，桌機壓縮成最多兩列。
- 搜尋、筆數與日期排序整合成一條工具列。
- 搜尋使用清楚的搜尋圖示按鈕，點擊後在同一列展開輸入框。
- 日期排序使用上下方向圖示，不顯示冗長說明。
- 所有按鈕保留 hover、focus、selected 狀態與可辨識的 `aria-label`。

## 新增收入與支出

- 表單標題只顯示「新增收入」、「新增支出」或編輯標題，不顯示英文眉題。
- 移除唯讀的「紀錄類型」欄位。
- 移除付款影響、退款方式與檔案格式限制等說明段落。
- 預算分類、人員等選項數量少時直接顯示為按鈕選項；超過可用寬度時橫向換行。
- 付款方式固定顯示未指定、轉帳、現金、信用卡、電子支付的精簡按鈕。
- 支出狀態直接顯示已付款、待付款；收入不顯示只有單一值的狀態控制，直接使用已入帳。
- 日期欄使用有日曆圖示的按鈕式輸入，點擊開啟原生日期選擇器並套用一致的外觀。
- 憑證只顯示「上傳憑證」卡片，支援點擊與拖放；選取後顯示檔名／張數。
- 備註保留但降低視覺權重。
- 底部按鈕統一為「取消」與「儲存」。

## 新增轉移

- 套用與收入／支出相同的標題、日期、付款方式、備註和底部按鈕設計。
- 轉出人與轉入人直接顯示人員首字按鈕，不使用下拉選單。
- 狀態直接顯示已完成、待處理、已作廢。
- 送出按鈕文字統一為「儲存」。

## 響應式

- 桌機表單維持兩欄；按鈕選項與上傳區可跨滿整列。
- 760px 以下表單改為單欄，modal 由底部滑入。
- 320px 寬度不得產生水平頁面捲動。
- 頂部導覽與篩選按鈕可在各自容器內水平滑動，但不擴張頁面寬度。

## 可用性與錯誤處理

- 保留既有 required、金額下限、人員必選、轉出與轉入不可相同等驗證。
- 檔案錯誤仍使用既有 toast；格式限制不以常駐說明文字占用畫面。
- 鍵盤可操作導覽、分段選項、日期、上傳與表單按鈕。
- modal 保留點擊外部與關閉按鈕的既有行為。

## 測試與驗收

- 單元測試覆蓋精簡付款方式文字、單一收入狀態與選項顯示規則。
- 驗證收入、支出、轉移提交資料與既有 API 格式完全相同。
- 瀏覽器驗證頂部導覽、目前頁籤、表單直接選項、日期選擇、上傳區與儲存。
- 驗證帳本第一列人員、第二列合併類型／分類、搜尋與排序。
- 驗證 320px、760px 與桌機，不得有頁面水平捲動。
- 執行 `npm test` 與 `npm run build`。
